## Как собрать полную папку из ветки и ассетов
```
git clone -b v2 <адрес репозитория> chem_constructor_v2 && cd chem_constructor_v2
# скачайте 6 ассетов в эту папку, затем:
for z in chem_constructor_v2.0-beta5_*.zip; do unzip -o "$z"; done
```
`.gitignore` ветки работает как белый список: в git попадают только `*.md`, `*.py`, `*.json`, `*.sh`, `LICENSE` и PNG-превью
(`02_molecules/*/*.png`, `05_flex_bonds/*.png`, `07_v2_new_elements/*.png`). Распакованные STL, 3MF, GLB, USDZ и zip в коммиты не попадут.
Параметрический исходник `00_source/chem_constructor.scad` в ветке не публикуется (см. «Лицензия» в README).

## Как собрать ассеты
Из корня ветки `v2`, когда бинарники лежат рядом (распакованы или сгенерированы конвейером): `sh make_release_assets.sh` → шесть zip в `release_assets/` (папка в git не попадает).

## Как выпустить релиз
1. Решить, выпускать ли beta как preview до снятия блокера из `STATUS.md` (выбор гибкой связи).
2. На ветке `v2`: `git tag -a v2.0-beta5 -m "v2.0-beta5 $(date +%Y-%m-%d)"`, затем `git push origin v2 v2.0-beta5`.
3. На GitHub: Releases → Draft a new release → тег `v2.0-beta5`, флажок pre-release → загрузить шесть ассетов из таблицы.
4. В описание релиза: статус beta, несовместимость с v1.0, что печатать первым, ссылка на `docs/KIT_v2_CATALOG.md` и `docs/CHANGES_v1_to_v2.md`.
