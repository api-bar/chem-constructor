# Хранение проекта в git: что хранить, что собирать, как выпускать

Проект «химический конструктор» — это параметрическая модель на OpenSCAD плюс Python-скрипты проверки и сборки. Исходники и результаты их работы нужно хранить по-разному. Ниже — правила разделения.

## 1. Что хранить в git (текст, небольшой размер)

| Что | Зачем |
|---|---|
| `chem_constructor.scad` — исходник модели | git показывает, какой параметр изменился и когда; вместо копий `…_v1.scad`, `…_backup.scad` |
| `chemlib.py`, `molecules.py`, `assemble3.py`, `docs.py`, `render.py`, `tousdz.py`, `verify.py` — скрипты | проверки, сборка молекул, генерация пластин и документации |
| `README.md`, `TODO.md`, `docs/` | описание механизма, печати, план развития, результаты тестов печати |
| `seat_cache*.json` (по желанию) | кэш посадок «паз ↔ конец связи»; пересчитывается, но на это уходят минуты |

## 2. Что не хранить в git (генерируется или тяжёлое)

| Что | Почему |
|---|---|
| STL, 3MF, GLB, USDZ, PNG | двоичные файлы: каждая правка геометрии перезаписывает их целиком, репозиторий быстро раздувается |
| готовые пластины, сборки молекул, архивы | воспроизводятся из исходников одной командой сборки |
| промежуточные папки (`v2/`, `v2flex/`, `asm_v2/`, `vt/`) | рабочие артефакты |

Ориентиры по размеру: один углерод 12–14 МБ, пакет v1.0 около 307 МБ. У GitHub лимит 100 МБ на файл, рекомендованный размер репозитория — до 1 ГБ.

Пример `.gitignore`:

```
*.stl
*.3mf
*.glb
*.usdz
*.usdc
*.png
*.zip
build/
v2/
v2flex/
asm_v2/
vt/
__pycache__/
```

Если нужно хранить отдельный эталонный файл (например, тестовую призму), добавьте исключение `!reference/test_prism.stl` или подключите Git LFS.

## 3. Как выпускать результаты: релизы

Печатные файлы публикуются как **релизы** (GitHub Releases или аналог), а не коммитятся.

1. Закончили этап → ставим тег: `git tag v2.0-beta4 && git push --tags`.
2. Запускаем сборку (раздел 4).
3. Создаём релиз по тегу и прикладываем архивы: детали, пластины по цветам, сборки молекул (GLB/USDZ), тестеры.
4. В описании релиза — список изменений и что нужно проверить печатью.

## 4. Что нужно добавить, чтобы совместная работа работала

1. **Одна команда сборки** (`make` или `build.py`): SCAD → STL → проверки → пластины → сборки молекул. Сейчас шаги разбросаны по отдельным скриптам.
2. **Проверки как автотесты** (подходят для CI, например GitHub Actions):
   - сетка герметична, одно тело;
   - нет послойных «островов» (печать без поддержек);
   - булева посадка каждой пары «паз ↔ ключ» (остаток около 0);
   - молекулы собираются без пересечений;
   - кольцо (циклогексан) замыкается;
   - у L-аминокислот правильная хиральность.
3. **Зафиксированная версия OpenSCAD.** Геометрия и время рендера зависят от версии и режима булевых операций; закрепите её в README или в докер-образе.
4. **Теги и ветки.** Версии фиксируются тегами (`v1.0`, `v2.0-beta5`). Долгоживущая ветка одна — `main`. Остальные вливаются в неё по готовности и удаляются. Набор v1.0 на теге `v1.0` не развивается.
5. **Лицензия.** Для аппаратных проектов подходят CERN-OHL или CC BY-SA; без лицензии формально никто не может использовать и дорабатывать проект.

## 5. Ограничения

- Результаты печати (что напечаталось, что треснуло, фото) в git не живут. Для них — issues или заметки в `docs/print-tests/`.
- Рендер углерода занимает около 5 минут. В CI тяжёлые детали стоит собирать отдельными задачами и кэшировать результат.
- Блокер релиза v2.0 (выбор гибкой связи) нужно вести как issue с тегом `release-blocker`, пока он не закрыт печатью тестовой пластины.

## 6. Рекомендуемая структура репозитория

```
chem-constructor/
├── src/
│   └── chem_constructor.scad
├── scripts/
│   ├── chemlib.py
│   ├── molecules.py
│   ├── assemble3.py
│   ├── docs.py
│   └── build.py
├── docs/
│   ├── GIT_WORKFLOW.md
│   └── print-tests/
├── tests/                 # автопроверки для CI
├── README.md
├── TODO.md
├── LICENSE
└── .gitignore
```

Каталог `build/` (STL, пластины, молекулы) создаётся сборкой и в git не попадает.
